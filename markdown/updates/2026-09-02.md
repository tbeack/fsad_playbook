# 2026-09-02 — Claude Code v2.1.258 / Codex CLI rust-v0.152.1

## Claude Code Changes

### New Features
- Added Claude Fable 5.1 (`claude-fable-5-1`), now the default Fable model — 1M context, $10/$50 per Mtok with $0.25/Mtok cache reads (v2.1.257)
- Added `CLAUDE_CODE_SUBAGENT_MODEL_FORCE` to apply `CLAUDE_CODE_SUBAGENT_MODEL` (or the main model) to every subagent, ignoring per-spawn and agent-definition model overrides (v2.1.257)
- Added `s` in `/effort` to change effort for the current session only, matching `/model` (v2.1.257)
- Added a Containment Escape rule to auto mode so cloud metadata-credential fetches, egress evasion, and cross-tenant reach are no longer auto-approved unless the environment marks them expected (v2.1.257)
- Added a one-time prompt in auto mode before the first file read outside the working directories, with the option to block such reads via `permissions.blockReadsOutsideWorkingDirectories` (v2.1.257)
- Added "Time format" (`timeFormat`) and `timeZone` settings (v2.1.257)
- Added a `/doctor` warning for stale sandbox mask files left by a killed session (v2.1.257)
- Added support for a gateway-supplied `description` on discovered `/model` picker entries (v2.1.257)
- [VSCode] Added collapsible ACCOUNT & USAGE / SESSION MANAGER sections, a model pill with Effort row, output style selection, collapse toggle for Ungrouped, and renamed "Delete session" to "Archive session" (v2.1.257)

### Changed
- Numerous internal/behavioral changes in v2.1.257 (gateway model discovery scoping, `managedSourcesBehavior` merge semantics, `/btw` history keybinding, `defaultMode: bypassPermissions` restriction, etc.) — no playbook-facing action.

### Fixed
- v2.1.258: Fixed Claude Code failing to launch on macOS 12 (Monterey), a regression from 2.1.255; fixed remote/scheduled sessions failing with "user messages must have non-empty content" after a re-sent permission approval.
- v2.1.257: large batch of bug fixes (settings reload timing, keybindings, background sessions, Remote Control, MCP, sandbox, prompt cache, VSCode) — internal/reliability fixes, no playbook action.
