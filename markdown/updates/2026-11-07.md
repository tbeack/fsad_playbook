# 2026-11-07 — Claude Code v2.1.319

Claude Code v2.1.319 is new (up from v2.1.318).

## Claude Code v2.1.319

### New Features
- Added `permissions.denyInsteadOfPrompting` setting: a tool call that would wait on a permission prompt is denied and the turn continues, in terminal sessions, subagents and teammates. → **Affects:** Claude Best Practices — Notable `settings.json` Keys callout
- Added `CLAUDE_CODE_DISABLE_FEATURE_FLAGS` env var, which stops feature-flag fetching without turning off telemetry. → **Affects:** Claude Best Practices — Environment Variables table
- Added support for MCP tasks in the terminal: an MCP server's task-declared tool call moves to the background right away. Added `CLAUDE_CODE_DISABLE_MCP_TASK_BACKGROUND` to opt out. → **Affects:** Claude Best Practices — Environment Variables table (next to `CLAUDE_CODE_MCP_AUTO_BACKGROUND_MS`)
- Changed self-paced `/loop` to end when a turn finishes without rescheduling, instead of scheduling a fallback wakeup; `CLAUDE_CODE_LOOP_KEEPALIVE=1` keeps the old behavior. → **Affects:** Claude Best Practices — `/loop` collapsible
- Added an "Earlier in this session" row to `/tasks` listing finished subagents, reopenable even after a restart. → **Affects:** Claude Best Practices — Cheat Sheet `/tasks` row
- Added `/claude-api latency-optimize` to find where Claude API code makes people wait. → **Affects:** No playbook impact (claude-api skill subcommand, not core CLI; deferred)
- Added several Claude apps gateway admin settings (`admin.pooled_conflict_rule`, `login_notice`, `CLAUDE_GATEWAY_LOG_FORMAT=json`, etc.). → **Affects:** No playbook impact (gateway-operator admin surface, out of scope for this playbook)
- Added an "Earlier in this session" / spend breakdowns to `/usage` for gateway users without a spend limit. → **Affects:** No playbook impact (narrow gateway-billing edge case)

### Security / Bug Fixes (reviewed, not actioned)
- Fixed a sandbox escape when creating a worktree; fixed a Bash permission bypass via a crafted environment prefix; fixed a case where auto mode's `CLAUDE_CODE_AUTO_MODE_SERVER=1` managed setting was ignored behind a gateway. → **Affects:** No playbook impact — these are patched vulnerabilities, not user-facing behavior to document; the playbook already states to stay current on updates.
- Large volume of other VS Code, Cloud sessions, Claude Tag, and gateway-specific fixes reviewed — none rose to playbook-documentation relevance at this scope.
