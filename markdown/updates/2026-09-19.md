# 2026-09-19 — Claude Code v2.1.277 / v2.1.278

## New Features
- Added AGENTS.md support: in a project with no CLAUDE.md, Claude Code reads AGENTS.md instead; change it under "Project instructions" in `/config` (not yet on Bedrock, Vertex or Foundry) → **Affects:** Claude Best Practices page (Project Anatomy / Codex Equivalent callout)
- Added `CLAUDE_GATEWAY_PROXY_IS_EGRESS_BOUNDARY=1` for Claude apps gateways whose only egress is a forward proxy → **Affects:** No playbook impact (enterprise gateway egress topology not covered by this playbook)
- Added an optional `headers:` map on Claude apps gateway upstreams, to send static headers to a proxy run in front of a provider → **Affects:** No playbook impact (gateway upstream config detail outside playbook scope)
- Added a line saying a background task's update is waiting when it finishes while a panel such as `/tasks` is open → **Affects:** No playbook impact (minor UI notice, not a documented flag/setting)
- Added an `Auto mode server` row to `/status` showing whether this session's auto mode classifier runs on the server → **Affects:** Notable Environment Variables table (`CLAUDE_CODE_AUTO_MODE_SERVER`)

## Changed
- Changed auto mode for Claude API and Enterprise users, and on Bedrock, Vertex, Foundry and gateways, to default to the server-side classifier, which does not charge for classifier overhead (`CLAUDE_CODE_AUTO_MODE_SERVER=0` opts out on Bedrock, Vertex, Foundry and gateways); warns on billed fallback → **Affects:** Notable Environment Variables table (corrects the v2.1.273 `CLAUDE_CODE_AUTO_MODE_SERVER=1` row, whose default/polarity this reverses)
- Changed workflow scripts' computed `agent()` prompts on Bedrock, Vertex, and Foundry to reach the subagent framed as script-authored text, so the safety classifier does not read them as the user → **Affects:** No playbook impact (internal prompt-framing hardening, no user-facing flag)
- Changed subagent results to reach the main agent under a header marking them as subagent output, with the result indented → **Affects:** No playbook impact (internal message-framing change, restores expected trust boundary already implied by existing docs)
- Removed the deprecated TaskOutput tool; Claude reads a background task's output file with Read instead → **Affects:** No playbook impact (playbook never documented the TaskOutput tool by name)
- Removed the background Haiku auto-title request from `claude -p` runs launched outside an SDK or IDE → **Affects:** No playbook impact (internal cost/latency optimization, no user-facing change)
- Large batch of reliability and correctness fixes (empty text block failures, hang/crash fixes across Grep/Glob/Write/Edit, plugin install/reinstall races, `/plugin` and `/skills` crashes, Remote Control session bookkeeping, PDF reads on Windows, headless resume cost totals, and more) → **Affects:** No playbook impact (bug fixes restoring already-expected behavior)
- VS Code- and Claude Code on the web-specific fixes and improvements (Sign out row, background shells in agent map, Copy response button, session cost/usage display, environment picker sections, network access dialog, and more) → **Affects:** No playbook impact (IDE extension and web-console internals outside this playbook's CLI-focused scope)
- Claude Tag-specific fixes (org-wide install channel reads, credential preset links, Pylon EU host, Google Cloud credential forms, network events log response status) → **Affects:** No playbook impact (Claude Tag/Slack admin surface not covered by this playbook)
