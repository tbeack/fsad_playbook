# 2026-09-10 — Claude Code v2.1.267 / Codex CLI v0.154.0

## Claude Code Changes

Covers the `2.1.267` CHANGELOG.md entry, since the last recorded version was `v2.1.266`.

### New Features
- Added `maxEffortLevel` setting (top-level or per model under `modelSettings`): caps the effort level on every provider, including Bedrock, Vertex and Foundry; users can still pick a lower level (v2.1.267)
- Added `--system-prompt-snapshot off` to render the system prompt fresh on every request instead of reusing the conversation's recorded prompt (for iterating on prompt text) (v2.1.267)

### Fixed
- Large cluster of prompt-cache reuse fixes (MCP tool re-sends, mid-session tool list rewrites, `/model` switches, disappearing tools, worker forks, resumed sessions, print-mode resume) — all restore previously-expected cache behavior; none change documented playbook guidance
- Fixed Workflow `agent()` calls with large output schemas being refused in auto mode instead of being checked by the safety classifier — restores expected behavior, not a new capability
- Fixed artifact publishes cut off by a dropped connection mid-upload (now retries once) and improved artifact publish error messages — reliability/UX polish, no documented behavior changes
- Fixed `effort:` frontmatter being ignored on models whose default effort is pinned (Opus 4.7, Opus 4.8, Fable 5) — restores expected behavior; the playbook doesn't currently document this limitation, so no correction needed
- Security fix: a marketplace/plugin path containing a backslash could bypass the containment check on macOS/Linux — already-fixed vulnerability, no user-facing doc action
- Various Cowork, Remote Control, VS Code, Claude Code on the web, and Claude Tag reliability fixes — internal, no playbook impact

### Improved
- Improved sandbox guidance to suggest `/copy` when clipboard commands (e.g. `pbcopy`) fail inside the sandbox — internal model guidance, not a user-facing setting or command change
- Improved the Bash tool's description guidance and various prompt-input/resume responsiveness — internal, no playbook impact
- Self-hosted runner and gateway (`forward_user_identity`) changes — niche enterprise routing, no playbook impact

## Codex CLI Changes

Covers the `rust-v0.154.0` GitHub release (release body; `CHANGELOG.md` on `main` only points to the releases page), since the last recorded version was `rust-v0.153.4`. Cross-referenced against `developers.openai.com`'s changelog redirect target (`learn.chatgpt.com/docs/changelog`), which lists `Codex CLI 0.154.0` (2026-09-09) as the newest entry with no further undocumented entries above it.

### New Features
- Experimental worktree support: `--worktree` / `/worktree` creates an isolated checkout for a new or forked session, with browse/resume support — not previously documented anywhere in the playbook
- Inline async questions: Codex can ask a question while continuing to work in the background, offering suggested choices or free text, without losing your in-progress draft reply — not previously documented
- `R` replace mode added to Vim editing (with undo and dot-repeat support) — the playbook's Vim Editing Mode section already documents `r<char>`, `.`, `/`/`?`, and `u`/`Ctrl+R` motion-by-motion as they shipped, so `R` is a direct addition to that same list
- `/copy` now preserves formatting when pasting into rich-text apps, and can copy status output or individual session fields (not just response text/code/blockquote) — extends the already-documented `/copy` picker behavior (rust-v0.150.0)
- GPT-6-Astra listed in the general model picker in addition to Amazon Bedrock catalogs — see Deferred; overlaps with already-completed CBP-528
- Windows sessions can share a background Codex server with managed daemon lifecycle commands — Windows-only platform feature, no playbook impact (playbook doesn't document a Windows-specific workflow)

### Changed
- `codex mcp-server` command, flagged as **deprecated** in the playbook's "Codex as MCP Server" callout (as of 2026-08-24), has now been fully **removed** (PR #42993) — the callout's wording needs updating from deprecated to removed

### Fixed
- Existing sessions now pick up newly installed plugin tools and refresh skills/hooks on external plugin upgrades/rollbacks without restart — quality-of-life fix; the playbook's Plugins section never called out the old restart requirement as a limitation, so there's nothing to correct
- MCP OAuth token refresh coordination, login-challenge surfacing, and safer replay handling — refines behavior already covered by the "OAuth reauthentication recovery" note (rust-v0.148.0); no new user-facing surface to document
- Startup hardening (workspace-controlled helpers, macOS sandbox terminal-input-injection blocking) — internal security hardening, consistent with already-documented trust-gating behavior (rust-v0.147.0/v0.150.0); no new user-facing behavior
- Remote resume/fork operations now preserve saved permissions; fresh sessions/forks respect server model defaults unless overridden — reliability fix for already-documented `codex exec fork` / remote-control behavior, no new capability
- Automatic-approval review context preservation through compaction/rollback — internal Guardian-review reliability, no playbook-facing change
