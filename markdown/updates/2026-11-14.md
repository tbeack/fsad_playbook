Claude Code v2.1.325 is new (up from v2.1.323; no v2.1.324 was published to npm).

## Claude Code v2.1.325

### New Features / Behavior Changes

- Sandboxed Bash commands now follow the normal permission flow by default instead of running without prompts; set `sandbox.autoAllowBashIfSandboxed: true` to keep the previous no-prompt behavior, including in managed settings that turn the sandbox on. → **Affects:** Claude Best Practices — Subprocess Sandboxing collapsible (Update existing)
- Scheduled tasks and `/loop` now ask before running a skill that declares `allowed-tools` or hooks; add `Skill(name)` to `permissions.allow` to run it unattended. → **Affects:** Claude Best Practices — `/loop` collapsible and `/schedule` row (Update existing)
- Claude is now told when an MCP task is waiting on your answer and can point you to `/tasks`. → **Affects:** Claude Best Practices — `/tasks` row (Update existing)
- Reviewed and deferred as no/low playbook impact at this scope: the zstd decoding security fix, the Jupyter re-run spinner tip, the organization-policy-block `/rewind`/`/clear` hint, `.claude` protected-file checkout notes, `--add-dir` vs. `additionalDirectories` for unprompted read-only git commands, `claude remote-control` exit codes, `CLAUDE_CODE_MAX_CONTEXT_TOKENS` on unrecognized `claude-` model IDs, scratchpad-folder instruction wording, plugin/marketplace trust-warning wording, Remote Control `/resume`/`/teleport` disconnect-first behavior, and the very large volume of other bug fixes and VS Code / Claude Code on the web / Remote Control / Claude Tag items reviewed this cycle — none rose to playbook-documentation relevance at this scope.
