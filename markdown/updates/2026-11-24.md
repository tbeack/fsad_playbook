## Claude Code v2.1.331

### New Features / Behavior Changes

- Added Code Mode support in terminal sessions on Amazon Bedrock, Google Cloud's Agent Platform, Microsoft Foundry and Claude Platform on AWS; improved Code Mode's tool search to show more of each MCP tool's description, including its limits, formats, and defaults. → **Affects:** Claude Best Practices — Code Mode collapsible (Update existing)
- Added an API connectivity section to `claude doctor` that reports whether the API can be reached, with the HTTP status or the error, or says why it wasn't tested. → **Affects:** Claude Best Practices — `/doctor` row (Update existing)
- Added `optionalDependencies` to plugin manifests: plugins that install with the plugin listing them and can be disabled or uninstalled on their own. → **Affects:** Claude Best Practices — Dependency enforcement bullet (Update existing)
- Improved the Console sign-in link shown by `/login` and `claude auth login --console`: it is now much shorter. → **Affects:** Claude Best Practices — `/login` row (Update existing)
- Changed in a future release, on or after November 30, 2026: plugin marketplaces in managed `extraKnownMarketplaces` will auto-update by default; opt one out with `"autoUpdate": false` on its entry. → **Affects:** Claude Best Practices — Plugins section (Add new bullet, flagging an upcoming default-behavior change)
- Reviewed and deferred as no/low playbook impact at this scope: `oidc.groups_jsonpath` for the Claude apps gateway, the tap-mode voice dictation stop notice, `CLAUDE_CODE_DISABLE_RESPONSE_COMPRESSION`, `CLAUDE_GATEWAY_IDP_CONNECT_BY_HOSTNAME`, the `gen_ai.usage.*`/`gen_ai.response.model` OTEL trace-span additions, the plugin auto-update notice separately naming newly-installed dependency plugins, the `PermissionDenied` hook `retry: true` semantics clarification, Yes-first ordering for a few confirmation questions, the artifacts list marking web pages, improved screen-reader typing speed and general start-up time, Windows managed-settings-in-registry precedence, and the very large volume of other bug fixes and VS Code-specific fixes reviewed this cycle — none rose to playbook-documentation relevance at this scope.

## Codex rust-v0.172.0

### New Features

- Added slash command completion: press Tab to complete arguments for supported slash commands, such as `/mcp lo` → `/mcp login`. → **Affects:** Codex Best Practices — Keyboard Shortcuts table (Add new row)
- Added agent command center navigation: `Shift+Up` and `Shift+Down` jump between task groups. → **Affects:** Codex Best Practices — Interactive dashboard paragraph (Update existing)
- Changed lazy MCP startup: optional stdio MCP servers with cached tool lists now start on their first tool call by default. → **Affects:** Codex Best Practices — MCP section (Add new note)
- Added per-tool approval reviewers: set an approval reviewer for individual connected app tools in `config.toml`. → **Affects:** Codex Best Practices — Permission Profiles paragraph (Update existing)
- Fixed `codex exec resume` to restore saved sandbox permissions, working directory, and workspace roots unless explicitly overridden. → **Affects:** Codex Best Practices — CI/CD Integration section (Add new note)
- Reviewed and deferred as no/low playbook impact at this scope: Amazon Bedrock Runtime selectable by app-server clients during setup/sign-in (niche, non-TUI client detail on top of already-documented Bedrock Runtime support), custom status lines exposed in `/experimental` (previously deferred as feature-flagged in rust-v0.171.0, still experimental), opt-in Guardian v3 message boards, opt-in OAuth discovery in config server loaders, Code Mode gRPC-only host connections (internal transport), `thread/sample` limit changes, sandbox integrity-check and denial-wait timing changes, connector-result routing changes, `/status` omitting unknown server versions, git worktree status timing, Python tooling hash verification, Windows sandbox provisioning/MXC changes, and the remaining bug fixes (resume/cross-platform session restoration, spend-limit error scoping, queued-reply preservation, realtime call handoff fixes, etc.) — all internal reliability or infrastructure changes, or niche enterprise/app-server-client details, with no broader workflow implication at this scope.
