Practical Reference for Daily Claude Code Use

Practical Best Practices

Concrete habits and mental models that keep sessions efficient, outputs focused, and token budgets healthy — drawn from real usage patterns across FSAD pods.

01 — Token Management

5 Habits to Never Hit Your Token Limits

Every new Claude Code turn re-sends your full conversation history as input tokens. Context accumulates — so later turns grow more expensive and model accuracy starts to degrade well before you hit the limit. These habits slow that growth.

1

Compact at 50%

Run /compact when your context reaches ~50% full — accuracy and consistency start degrading around the halfway mark, not at the limit. Compacting early eliminates old tool outputs, summarises decisions already made, and reduces the history re-sent on every new turn.

2

Name the Exact File

Reference the specific file, not the directory. A targeted single-file read is orders of magnitude cheaper than recursive folder exploration — and gives the model only what it actually needs, not everything that happens to be nearby.

✓ src/auth/handler.ts ✗ src/auth/
3

Order Matters

After a compact, old messages cost more to carry than new ones. Re-state the file you need immediately after compacting so Claude doesn't have to re-read it from the summarised history. Name the resource first; ask the question second.

4

Plan Before You Build

Ask for a plan first, review it, then ask for the implementation. A single planning round costs a fraction of a failed multi-step implementation. One focused task per session beats five interleaved ones.

research → plan → implement
5

End Each Task with /compact

Before switching to a new task in the same session, run /compact to summarise and discard the completed work's context. Carry-over messages from a finished task inflate the window for the next one — even if that context is no longer relevant.

compact between tasks one job per context
02 — Effort Calibration

Match Effort to the Task

Claude Code's effort setting controls how deeply it reasons before responding. Over-efforting simple tasks wastes tokens; under-efforting complex ones produces shallow work.

low / medium

Quick asks, formatting, simple refactors, and boilerplate. Use when the task requires no sustained reasoning chain.

rename a variable format JSON add a comment
high
default on Opus

Real coding, debugging, and refactoring. The right setting for most daily FSAD work — deep enough to reason about dependencies without burning tokens on simpler tasks.

feature implementation bug fix refactor
xhigh / max

Complex architectures, hard cross-cutting bugs, and novel problems with no clear prior. Reserve for tasks where the cost of a shallow answer is high.

system design security audit hard debugging
Quick reference

Effort commands

/effort low       # exploration, quick questions
/effort medium    # default on Sonnet; most lightweight tasks
/effort high      # default on Opus; standard daily FSAD work
/effort xhigh     # deep reasoning, slower output
/effort max       # maximum reasoning budget

Effort persists for the session. Reset it explicitly when switching task types — e.g. drop back to /effort medium after a hard debugging session to avoid over-spending on a simple rename.

03 — Session Hygiene

Set Once, Forget

Things you should configure once so you never have to repeat them in a prompt. Every repetition is a token cost and a cognitive tax.

Pattern 1

Write a CLAUDE.md

Any behavior you find yourself re-stating each session belongs in CLAUDE.md. The model loads it at the start of every session — you never have to say it again.

## Constraints
- Never add comments explaining what the code does.
- Always run the build script before committing.
- Use TypeScript strict mode; no `any`.
- Ask before running destructive git commands.

Scope it to the project: repo-level CLAUDE.md for project conventions, ~/.claude/CLAUDE.md for personal habits that apply everywhere. Nested CLAUDE.md files in subdirectories load on-demand when Claude works in that directory.

Pattern 2

Problem First, Code Second

Always describe the problem before asking for code. "Here's what's broken and why it matters" is cheaper than three rounds of rejected implementations because the model guessed wrong about the goal.

✓ explain the problem ✓ share the constraint ✗ jump straight to "write me..."
Pattern 3

Right Tool for the Depth

Don't use dynamic workflows (ultracode) for anything a single focused session can do. Spawning 20 agents to rename a variable costs 20× and delivers the same answer. Reserve multi-agent orchestration for genuinely parallelisable work.

single-agent default multi-agent for parallel scope
Pattern 4

Use Hooks for Repeating Checks

If you always want something checked before or after a tool call (e.g. lint after every file write, confirm before destructive git commands), encode it as a hook — not a prompt instruction that silently disappears after /compact.

"hooks": {
  "PostToolUse": [{
    "matcher": "Write",
    "hooks": [{"type": "command",
      "command": "npm run lint"}]
  }]
}

Hooks are shell commands wired to lifecycle events — they fire regardless of what's in context. Instruction files (CLAUDE.md, .claude/rules/) are re-injected after /compact automatically. Conversational instructions you gave mid-session are not — they get summarised away.
